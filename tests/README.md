# Tests

| Path | What it is |
|---|---|
| `smoke.mjs`, `match_smoke.mjs`, `play_smoke.mjs` | quick checks that the WebAssembly engine loads and its API works |
| `corpus/` | test positions and match files (generated by native gnubg; see `corpus/README.md`) |
| `native/` | runs **native** gnubg to produce reference results (`native/PYTHON_INTERFACE.md` explains every number) |
| `wasm/` | replays the same queries through the **WebAssembly** engine |
| `compare/` | compares two result files and prints the tables; `compare/repro/` has minimal reproductions of the differences found |
| `reference/` | result files (`*.json`, git-ignored, about 9 MB each) and `RESULTS.md` (the Phase 2 results) |
| `lib/engine-node.mjs` | loads the WebAssembly engine in Node |
| `repro/` | reproduces the (resolved) history-dependence issue from Phase 1 |

## Phase 2: WebAssembly vs native, end to end

Run from the repository root. Times are for an Apple Silicon Mac (Node 24).

**0. Once: build the two native reference builds** (needs Homebrew `glib pkgconf python3`;
a few minutes each; skip if `engine/native/build/<variant>/gnubg` exists).

```sh
engine/native/build-native.sh strict
engine/native/build-native.sh release
```

**1. Native reference results** (strict build, one fresh gnubg process per query): 41 s.

```sh
tests/native/run_native.sh strict fresh
```
writes `tests/reference/native-strict-fresh.json`.

Optional extra references:

```sh
tests/native/run_native.sh strict single-clear     # one process, cache flushed per query: 32 s
tests/native/run_native.sh release fresh            # gnubg's own -O3 -ffast-math flags: 48 s
ANALYSIS_PRESET=supremo MATCHES_ONLY=1 tests/native/run_native.sh strict fresh
                                                    # matches at gnubg's default analysis settings: 52 s
```

**2. WebAssembly results** (one engine instance, replaying the native file query by query): 48 s.

```sh
node tests/wasm/run_wasm_reference.mjs
```
reads `tests/reference/native-strict-fresh.json`, writes `tests/reference/wasm-strict.json`.
For the default-settings matches (84 s):

```sh
node tests/wasm/run_wasm_reference.mjs tests/reference/native-strict-fresh-supremo.json tests/reference/wasm-strict-supremo.json
```

**3. Compare** (under 1 s each); prints markdown tables.

```sh
python3 -I tests/compare/compare.py tests/reference/wasm-strict.json tests/reference/native-strict-fresh.json
python3 -I tests/compare/compare.py tests/reference/wasm-strict.json tests/reference/native-strict-single-clear.json
python3 -I tests/compare/compare.py tests/reference/native-strict-fresh.json tests/reference/native-release-fresh.json
python3 -I tests/compare/compare.py tests/reference/wasm-strict-supremo.json tests/reference/native-strict-fresh-supremo.json
```
Add `--details N` to list more individual differences (default 40).

The output of these four commands, with a plain-English summary, is
`tests/reference/RESULTS.md`.

### What to expect

WebAssembly vs native strict: every number bit-identical except (1) the order of moves
whose equities are exactly tied, and its knock-on effect on which tied moves get the
deeper evaluation, and (2) one statistic computed with `log10f`. Both come from the C
library; see `RESULTS.md` and `compare/repro/`. Anything else is a bug to investigate,
not a tolerance to widen.

### Notes

- `run_native.sh` modes: `fresh` (one gnubg process per query; the reference),
  `single-clear` (one process, gnubg's cache flushed before each query; identical
  results, much faster for the positions), `single` (one process, no flushing; results
  depend on the query order, see `native/PYTHON_INTERFACE.md` section 9).
- The WebAssembly API flushes gnubg's evaluation cache at the start of every
  evaluating call, so one engine instance corresponds to native `fresh`.
- If the corpus is missing, `run_native.sh` falls back to the small sample in
  `native/sample/` (and says so).
- `.mat` money sessions are imported with gnubg's default "Jacoby on" (the format has
  no Jacoby flag). `run_native.sh` passes `JACOBY` through to the match script for
  native experiments; the WebAssembly API always uses gnubg's default.
